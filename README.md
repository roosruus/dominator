# Shuffle My Kingdom

A kingdom randomizer for the [Dominion](https://www.riograndegames.com/games/dominion/) deck-building card game.

Choose the expansions you own, press **Shuffle**, and the app deals 10 random kingdom cards along with any extra
setup components those cards need. It can also apply a set of "recommended rules" that steer the shuffle away from
lopsided or degenerate kingdoms.

## Features

- **Expansion selection**: pick any combination of the supported sets, and include or exclude individual cards
  within each set.
- **Per-expansion limits**: set a minimum and maximum number of kingdom cards to draw from each expansion.
- **Additional setup cards**: automatically lists the extra components a kingdom requires, for example:
  - Potion when any Alchemy card costs a potion
  - Platinum and Colony, and Shelters, with a probability based on how many Prosperity or Dark Ages cards are in
    the kingdom
  - Prizes for Tournament
  - Ruins, Spoils, Madman and Mercenary for the Dark Ages cards that use them
- **Recommended rules** (optional toggle) that aim for a playable, varied kingdom, including:
  - at least one card each giving +Buy, +Cards and +Actions
  - a balanced cost curve (e.g. 1–3 cards costing 2, 2–4 costing 5, at most one costing 7)
  - at most 2 Attacks, at most 1 hand-reducing Attack and at most 2 curse-giving Attacks
  - mutually exclusive groups of cards that play too similarly (e.g. Throne Room / King's Court, Smithy / Envoy)
- **Saved selections**: your expansion, card and rule choices are kept in the browser's `localStorage`.

### Supported sets

Dominion (1st and 2nd edition), Intrigue (1st and 2nd edition), Seaside, Alchemy, Prosperity, Cornucopia,
Hinterlands, Dark Ages, Guilds, Adventures, Empires, Nocturne, Renaissance, and Promotional cards.

## Tech stack

- React 19 with function components and hooks
- Redux Toolkit for state, Material UI 9 for the interface
- Vite 8 for the dev server and bundling, Vitest and Testing Library for tests, ESLint 10 for linting
- Firebase Hosting for deployment

## Getting started

Requires Node.js 24.15 or newer (see `.nvmrc`). The project's `.npmrc` pins the public npm registry, so installs
work regardless of any registry set in your global npm config.

```sh
npm install
npm start          # dev server at http://localhost:5173
```

## Card data

The card list in `src/webapp/data/cards.json` is generated by `scripts/updatecarddata.cjs`, which scrapes the
[Dominion Strategy card list](https://dominionstrategy.com/all-cards/). Besides each card's name, set, types, cost
and text, the script derives fields the randomizer uses:

- `plusCards`, `plusActions`, `plusBuys`, `plusCoins` parsed from the card text
- `categories` such as `gaincurse`, `gainspoils` and `handreducing`
- `partOf` for cards that belong to a split or mixed pile (Knights, Ruins, Shelters, Empires split piles)

It also copies the cards shared by both editions of Dominion and Intrigue into the 1st edition sets and patches a
few gaps in the source data. If the source page changes, the scraper is the place to fix things.

```
  store/                     Redux Toolkit slices, selectors and localStorage persistence
src/test/                    test setup and helpers
```

### How picking works

The engine (`src/webapp/engine`) starts from all cards, filters out non-kingdom cards (Events, Landmarks, Prizes,
Ruins and so on), then applies the current rules: which sets and cards are included, per-group min/max limits, and
sets of cards that must not appear together. Groups can match a set, a card type, a category, or a numeric property
like cost or +Actions, and can be combined into compound groups.

Picking is a greedy pass over the shuffled pool: first any explicitly required cards, then cards needed to meet each
group's minimum, then the remaining slots, skipping any card that would break a maximum or a "not together" rule.
Limits are best effort, so a very restrictive setup can produce fewer than 10 cards.

## Deployment

The app is hosted on Firebase Hosting and serves `build/dist`. Create a `.firebaserc` pointing at your Firebase
project (it is git-ignored), then run:

```sh
npm run deployToFirebase
```
